## 二、本轮（2.18.77）最关键的新发现：真实宿主里插件根本没激活

按复核要求用**真实 DSH 宿主 + 隔离 `DSH_HOME`** 跑装/升级/卸时，发现：

```
desktop-control (dsh-desktop-control): pending (waiting for service: workspaceRegistry)
```

`cordis.patch.yml` 与模块导出的 `inject` 都把 `workspaceRegistry` 列为**必需**。
在 headless 这类没有该服务的 profile 里，插件永远 pending，**25 个工具一个都不注册**。
mock 宿主提供这个服务，所以 550+ 条测试和 17/17 都没发现。

修法：`inject` 只保留真正必需的 `tools`/`approval`；`agents`/`workspaceRegistry`/`attachments`
改用 `ctx.get()` 可选获取（缺了也不阻止激活）。两处声明必须一致——实测只改 YAML 不够。

修复后在真实宿主上：旧版 pending → 升级后激活 → 卸载后 bundles/依赖干净、宿主正常重启。
完整命令与输出见 `真实宿主-隔离profile-装卸记录.md`。

## 四、上一轮逐条处理（对应复核第 1–6 条）

### 1. P1 原生光标恢复的两个分支

- `Fx.cs` 心跳停止分支：恢复成功才清 `blanked` 与标记；**失败则保留状态、退避 2 秒后继续重试**，不再退出
- `Fx.cs` inactive 分支：同样改为成功才清；失败保留标记并稍后重试
- `Guard.cs` hostGone：恢复失败时**不再退出**，保留标记并 2 秒后重试（否则磁盘上只剩标记，没有进程执行恢复）

### 2. P1 `guard.ready` 陈旧判断

- 插件每次启动生成 `runId`，同时传给 fx 与 guard
- guard 写入 `{"runId": "...", "pid": N}`；fx 校验 **runId 匹配 + PID 仍存活**
- fx 在**运行中**也会复查就绪：看门狗消失/被替换 → 立即恢复系统光标并暂停隐藏
- 兼容旧格式（纯 PID），但必须有活进程

### 3. P2 恢复成功判定

```js
const helperSaysOk = r.ok === true && r.data && r.data.ok === true
```

`{}`、缺字段、`ok:null` 一律按未确认处理（不再用 `!== false`）。

### 4. P2 桥的 Halted 返回协议

- PowerShell 急停分支现在**直接输出** `{ok:false, error:"Halted", invoked:false, ...}` 并 `return`（不再落入通用 `ok:true`）
- Python 保留结构化错误
- `toolset` 把桥的 `Halted` 映射成 `code=Halted`、`retry=stop`，不再走坐标补点或 NotFound 兜底

### 5. P2 诊断恢复命令

`desktop_diagnose` 现在用公共函数生成：

```powershell
$env:DSC_HALT_GATE='<实际闸门>'; & '<实际 helperPath>' stop --clear
```

路径用 PowerShell 单引号引用并转义单引号，helper 用实际 `helperPath`（不再是 `escPath` 推导）。

### 6. P2 测试与说明

- `test-clean-profile`：按文档顺序**先移 bundle 引用再 pnpm remove**，并断言卸载后 bundles 不含该插件
- `test-cursor-failure`：失败分支改为 `bad()`；统计真实启动尝试与 ENOENT
- 安装说明：卸载等待改为分阶段描述（5 秒 + 最长 8 秒）；"25 秒内退出并恢复""任何情况下都能救回来"改为条件式表述
