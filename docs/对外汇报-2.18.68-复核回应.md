## 0. 先认一条：上一版我对 B 项的解释是错的

你在同一次调用里做了三位置对照——同父进程、三份哈希相同的 exe，只有位置不同：

| 位置 | 自报 |
|---|---|

这直接否掉了我的"父进程不同"解释。你找到的机制是对的：

已改正，并采纳了你的建议（见 §2）。

## 1. 本版修掉的卸载缺陷（你反馈的孤儿进程）

**现象**：卸载后 `dsc-fx.exe` 与 `dsc-guard.exe` 残留，要手动停；
而且顺序错了会互相拉起。

**根因有两个**：

1. 插件每次桌面操作都会 `start()`，只要它还活着，就会把已经停掉的那个**重新拉起**
2. `dsc-guard` 只在收到 `fx.stop` 时退出；插件被卸载时没人写这个文件，它就永远挂着

**修法：让两个子进程自己会死，不依赖插件"记得"杀它们。**

```
插件每 5 秒写一次 fx.heartbeat
  ↓ 插件消失 / 卸载 → 心跳停止
dsc-fx   25 秒内自动退出 + 恢复光标
dsc-guard 同一条件（心跳停）立即恢复并退出
```

另外插件卸载时仍会先调 `stop()`（写 `fx.stop` + 按进程名兜底 `taskkill`），
所以**正常卸载是立刻收掉的**；心跳只是保证"哪怕 dispose 没被触发"也不会留孤儿。

**实测**（`tools/test-cursor-orphan.mjs`，不发任何停止信号、只停心跳）：

```
✓ 装饰进程已接管光标
✓ 两个进程都在跑
✓ dsc-fx 已自行退出（23 秒）
✓ dsc-guard 已自行退出（23 秒）
✓ fx.blanked 已清除（光标已恢复）
```

**卸载文档也改了**：等 25 秒即可，不用手动杀；想立刻收也行，
`taskkill /IM dsc-fx.exe /F` + `taskkill /IM dsc-guard.exe /F`，**顺序无所谓**。

## 2. 上一轮你提的两条建议（已实现）

### 2.1 `ping` 报自身文件的完整性标签

```
dsc.exe ping
→ "integrity": "Low",        "integrityRid": 4096,
  "exePath": "...\\dsc.exe",
  "exeFileIntegrity": "Low",  "exeFileIntegrityRid": 4096
```

实测对照：工作区副本 = `Low / Low(4096)`；`%TEMP%` 副本 = `Medium / 未知`。
实现是读文件安全描述符里的 `SYSTEM_MANDATORY_LABEL_ACE`，不是按路径猜。

### 2.2 `desktop_diagnose` 增加「光标装饰」一节

```
== 光标装饰 ==
  开关文件  : 有（内容 "blank"）/ 无（默认关闭）
  运行状态  : 正在接管光标（装饰进程 pid=27940）/ 未接管（停手 30 秒后会自动恢复，属正常）
  当前姿态  : 2
  最近日志  : 19:59:31.442 pose 2
  看门狗    : 19:59:33.042 恢复光标（装饰进程 27940 已退出）ok=True
```

agent 自查彩蛋状态不用再翻沙箱。
