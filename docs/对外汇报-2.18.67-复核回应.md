## 0. 先认一条：B 项我解释错了

你在同一次调用里做了三位置对照——同父进程、三份哈希相同的 exe，只有位置不同：

| 位置 | 自报 |
|---|---|
| profile | Medium |
| 工作区内 | **Low** |
| `%TEMP%` | Medium |

这直接否掉了我的"父进程不同"解释。你找到的机制是对的：
**DSH 的 ACL 沙箱把工作区目录标成 Low，文件继承标签；带 Low 标签的可执行文件启动后，进程就是 Low。**

我原汇报里"代码读的是真实令牌"这句话没错，但"为什么不同"解释错了。已改正，并采纳你的建议。

## 1. 本版改动（2.18.67）

### 1.1 `ping` 报自身文件的完整性标签（你的建议）

```
dsc.exe ping
→ "integrity": "Low",     "integrityRid": 4096,
  "exePath": "...\\dsc.exe",
  "exeFileIntegrity": "Low",   "exeFileIntegrityRid": 4096
```

实测对照：

| 位置 | 令牌 | 文件标签 |
|---|---|---|
| 工作区副本 | Low | **Low (4096)** |
| `%TEMP%` 副本 | Medium | 未知（无标签） |

实现是读文件安全描述符里的 `SYSTEM_MANDATORY_LABEL_ACE`（`GetNamedSecurityInfoW` +
`LABEL_SECURITY_INFORMATION`），不是按路径猜。

### 1.2 `desktop_diagnose` 增加「光标装饰」一节（你的建议）

```
== 光标装饰 ==
  开关文件  : 有（内容 "blank"）/ 无（默认关闭）
  运行状态  : **正在接管光标**（装饰进程 pid=27940）/ 未接管（停手 30 秒后会自动恢复，属正常）
  当前姿态  : 2
  最近日志  : 19:59:31.442 pose 2
  看门狗    : 19:59:33.042 恢复光标（装饰进程 27940 已退出）ok=True
```

这下 agent 自查彩蛋状态不用翻沙箱了。
