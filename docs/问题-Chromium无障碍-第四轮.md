# 第四轮：按第三轮复核修的，以及撤回的结论

> 对应《给大肥鱼的Chromium第三轮复核-2.18.17.md》。这一轮主要是**撤回**。

---

## 一、撤回的三个推论

### ① WinForms 对照不能证明原生 provider 路径

**我写的**：

```
FrameworkId == WinForm → 已证实应用自己的原生 UIA provider
FrameworkId == Win32  → 已证实系统 MSAA 转换代理
```

**两个都要删。** 复核说得对：

> Windows 也通过客户端代理支持标准控件，包括 Windows Forms 场景；客户端代理完全可以暴露真实名称、角色、矩形和动作能力。读到 12 个可交互候选，与走代理并不矛盾。
>
> FrameworkId 表示元素所属的 UI 框架，**不表示 provider 位于哪一侧**。

**正确的说法**：

> WinForms 功能对照通过，说明**客户端不是全面失效**。
> 该测试**未确认 provider 路径**，尚不能排除 Chromium 特定的入口、客户端兼容性、目标配置或访问条件问题。

### ② `UiaHasServerSideProvider=false` 也不是"什么都不是"

**我上一轮那么说是过头的。** 复核：

> 在查询正常返回的前提下，它是针对该 HWND 的服务端 UIA 检查结果；它与客户端能经其他路径读到子控件可以**同时成立**。
> 你目前没有独立证明测试靶的这个 HWND 应该返回 TRUE，所以这次结果**不是 API 失效的反证**。

**结论**：它是个事实，只是**我证明不了它对应什么**。

### ③ 三个目标不能互相补证

**我原来写**："三个目标（Edge/SuYou/DSH）framework 都是 Win32，点查询和根遍历都只有外壳"。

**复核**：

> Edge 的有效内容窗口尚缺点查询；DSH 本轮没有展示与 SuYou 等量的有效点查询记录。
> 第六节"三个目标点查询和根遍历都只有外壳"的概括，应改成**逐目标证据表**，不能用同为 Win32 互相补证。

**改成逐目标的说法**（复核建议的措辞）：

> **SuYou**：本次调用中，根遍历及四个采样点均未取得可用细粒度内容；原生 UIA 对照未执行，具体原因未知。
>
> **Edge**：已有根遍历未取得可用内容；正常网页窗口的有效点查询未完成。

## 二、修的两个代码缺口

### ① 角色分类数值错了（影响结论含义）

| 角色 | **官方值** | 我原来 |
|---|---|---|
| **Link** | **30** | 当成 42 ❌ |
| **StaticText** | **41** | 当成 42 的一部分 ✓/✗ |
| **Text** | **42** | 当成 LINK ❌ |

**后果两个方向都有**：
- **真正的链接漏计** → 只有链接的页面被说成 `shell_only`
- **静态文字增加 interactiveCount** → 只有文字的页面被说成 `has_candidates`

**修为**：
- 用官方数值
- **拆成两个概念**：`contentEvidence`（有内容吗）和 `actionCandidates`（能操作吗）
- "没有可操作元素"**不再推出**"只是外壳"（一段文字也有内容）

### ② `get_accChild` 量了但没用

**复核**：

> [Msaa.cs:289] 仍把所有整数孩子直接设成 `SimpleChild=true`。遍历器遇到这个标记便不再展开。
> [PointQuery.cs:239] 虽然调用了 get_accChild，但成功后仅做 `promoted++`。返回对象**没有替换孩子引用，也没有被遍历**。

**所以**：完成的是"采样诊断能否取得独立对象"，**不是**"遍历器已支持整数引用到完整对象的转换"。

**修为**（按复核给的协议）：

```
完整 IAccessible → Owner=该对象，ChildId=SELF，继续遍历
整数 childId → get_accChild(childId)
    得到完整对象 → 替换为该对象，ChildId=SELF，继续遍历
    正常返回无对象 → 保留父对象+childId，作为叶节点
    查询失败 → 记录 unresolved，不假装确认了叶节点
```

**保留 `RawKind` / `ResolvedKind`**，诊断仍能统计"原始整数孩子里有多少被解析成对象"。

**补了测试**（复核要求的）：根枚举出整数 ID → 该 ID 解析成带孙节点的对象 → **最终必须读到孙节点**。

`selftest_walk` 现在 **12 项**。

## 四、明确记录为"未做"的

```
nativeUiaComparison = not_run
```

**理由**（复核同意的排期判断）：

> 可以因为当前产品优先级选择暂缓；不能因为 WinForms 通过，就说原生对照已经被间接证明没有价值。
> 若现在优先完成能用的桌面操作，则明确记录 `nativeUiaComparison=not_run`，直接推进视觉通路也合理。**这是排期选择，不是已经排除技术可能性的证明。**

**所以我不再说"原生对照没价值"** —— 只是**这轮不做**。

## 五、点查询现在的结论强度

**复核指出**：

> 当前 PointQuery.cs:63 选的是窗口中心和几个比例偏移点；入口传入 GetWindowRect，注释却称"内容区"。这些点**不保证落在真正的按钮/输入框上**。
>
> 因此"四个点均返回容器"比根遍历多了一条**独立观察**，但**不是整页没有细元素的证明**。

**我接受这个限定**。而且他说得对：**目标是前台也不保证没有置顶覆盖**，`WindowFromPoint` 的归属和随后 UIA/MSAA 返回对象的归属**也不是同一个断言**。

**下一版该做的**：从截图里选 1–2 个**明确可见控件**的内部点，记录截图、坐标、返回角色、矩形，并同时记返回元素的进程/窗口信息。
