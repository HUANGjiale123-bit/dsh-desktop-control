## 一、两个变异，修复前后

### M1：禁用成功分支

```csharp
// 保留 resolver 调用，但让 if (acc != null) 恒不成立
if (false && acc != null) { ... }
```

| 版本 | 测试 | 生产路径访问节点 | 孙节点 |
|---|---|---|---|
| 修复前 | **16 项全过** | 2 | 否 |
| **修复后** | **4 项失败** | — | — |

**为什么之前测不到**：我只覆盖了"resolver 返回 null"和"resolver 抛异常"，**没覆盖"返回对象并被使用"**。

而且我在源码里写了"完整对象分支纯内存测不了" —— **那是逃避**。复核说得对：

> 生产测试可通过**适配层/测试替身**覆盖这段逻辑；真实 COM 路径另测，
> **不能把两层都当成无法测试而跳过**。

**验证过`class` 可以实现 `IAccessible`**（补全 `accSelect`、`accParent`/`accFocus`/`accSelection` 属性之后编译通过），于是有了 `FakeAccessible`。

新增 4 项断言：

```
✓ 整数 + resolver 返回对象 → SimpleChild=false（可展开）
✓ Owner 被替换成 resolver 返回的那个对象
✓ ChildId = CHILDID_SELF(0)
✓ ResolvedKind=object
```

### M2：切断失败传播

```csharp
// 设原因但不设 Failed
r.FailReason = r.FailReason ?? why;
```

**复核给的实际结果**：

```
子元素 ResolvedKind = unresolved
枚举 FailReason = get_accChild:InvalidOperationException
枚举 Failed = false          ← 这里
顶层 TraversalComplete = true
顶层 TruncatedBy = null
errors = []
```

**修复**：
- `r.Failed = true` 一起设
- 转换抽成 `Msaa.EnumResult.ToWalkPage()`（可测）
- `Probe` 的匿名委托改成调它

**验收**（第 7 项，3 条断言）：

```
✓ 枚举失败 → WalkPage.FailReason 有值
✓ 遍历器把失败报成 TraversalComplete=false
✓ 截断原因非空
```

**变异验证**：把 `ToWalkPage` 里的 `if (!string.IsNullOrEmpty(why))` 改成 `if (false)` → **3 项失败**。

### 顺带修的

**resolver 返回非 `IAccessible` 的东西**（比如一个字符串）原来归为 `simple` —— 那是"无法解释的返回"，不是"确认的叶子"。现在归为 `unresolved` 并记类型。

## 三、还没做的（阶段任务的 2–5 条）

### 第 2 条：坐标契约 —— **这是当前最大的缺口**

**现状**：

```
helper 截图      → 存文件，只返回 ok/path
toolset          → 读窗口矩形，返回 originX/originY/width/height
前端             → 把图缩到合适大小显示
模型             → 看到缩放后的
```

**工具不知道自己输出的图被缩放成多少**，所以"图像坐标 → 桌面坐标"这一步**仍然留给模型猜**。

**复核的原话**：

> **由代码完成图像坐标到桌面坐标的转换**，不再把未知预览比例留给模型猜。

**两条候选路**：

**A. 工具主动缩放截图**
```
截图后按固定宽度（如 1400）生成缩放副本
shotId 记录 { imageWidth, imageHeight, scale, originX, originY }
click 支持 space:'image'，用记录的比例换算
```
**彻底消除歧义，但要动截图链路。**

**B. 模型报告它看到的尺寸**
```
desktop_click({ shotId, x, y, imageWidth: 1400 })
```
**便宜，但仍要模型提供一个数字 —— 不满足"由代码完成"。**

**我选 A，但这是半天到一天的活，而且碰截图链路。** 今天已经在这条链路上摔过一次（2707 个 CR 混进字符串字面量）。

### 第 3 条：完整操作闭环

**做过一次**（SuYou 点「我的」），但**没记录图像尺寸和变换** —— 所以它只证明"在那个特定尺寸下走通了"，**不满足第 2 条之后的要求**。

### 第 4 条：多条件覆盖

```
原始图像 / 受控缩小后的定位图像 / 窗口移动 / 窗口改尺寸 /
截图后内容变化 / 被遮挡
```

**全未做。** 而且"变化无法可靠判断时应重新观察或明确停止"这条要求，现有代码**只对窗口几何做校验**，对内容变化没有检查。

### 第 5 条：交付物

```
源码差异 ✓（git log）
可运行测试 ✓（selftest_walk 24 项）
实际截图/日志 ✗（只有 shotId，没有可复核的落盘文件副本）
结果表 ✗
主要耗时 ✗
```
