# 视觉兜底：候选层、本地 OCR、两个工具（2.18.38 → 2.18.39）

> 依据外部评审的《轻量视觉兜底实现指引》，**方案改了一处**：OCR 不再打包
> RapidOCR/onnxruntime，改用 **Windows 自带的 `Windows.Media.Ocr`** ——
> "让别人用自己的机器 OCR"。实测零安装、本机 98~290ms。

## 三条硬约束怎么落地的

1. **坐标只算一次**：`viewPointToWindow(snapshot, view, {u,v})` 是唯一入口，
   返回 `space:'window'`；**不加窗口原点、不乘 DPI**（原点由 `toolset.click`
   的 `space:'window'` 分支加）。越界抛 `OutOfRange`，**绝不 clamp**。
2. **证据与结论分开**：OCR 分数只进 `scores.textRecognition`；
   候选的 `role` / `actionability` 恒为 `unknown`；`kind` 只写来源真正知道的
   （`text` / `point`）。
3. **ID 不透明 + 级联失效**：`candidateId` 随机生成；作废一张截图会同时带走
   它的 view 和 candidate，`invalidateOwner` 处理换会话/撤权。

## 踩到的两个坑（都写进注释了）

1. **WinRT 的 `StorageFile.GetFileFromPathAsync` 不吃正斜杠路径**。
   `C:/Users/...` 会抛 `E_INVALIDARG`，包在 `IAsyncOperation` 里表现成
   `Wait 时发生一个或多个错误` —— 完全看不出是路径问题。`ocr-worker.mjs` 里统一转反斜杠。
2. **测试要截图时不能用 `%TEMP%`**：helper 跑在 Low 完整性下，写工作区之外被沙箱拒
   （`OutputNotWritable`）。测试改成落在 `.cache/` 下。
   ——"出题人比被测进程权限高"时，不能按自己的方便挑目录。

## 最低验收集现在到哪了

评审列了 8 条，这一批覆盖第 1、2 条，并且是**真机真截图**：

## 实测发现的两件事

1. **复查余量 12px 会把邻居吃进来**。第一版用 12px 余量，候选「剩余流量」旁边就是
   实时流量计数，于是每次复查都判"内容变了" —— 误拒率 100%。改成 4px
   （能看出位移与覆盖，又不至于把邻居框进来），并把"误拒要靠真实任务统计"写进注释。
2. **真实应用的窗口在我们跑测试期间被移动过好几次**（空闲时不移动，也不像测试干的：
   助手侧的 `click` 只做 SetCursorPos + down/up，激活层不动坐标）。
   后果是"截图里的那块区域"和屏幕上的不是同一块，复查这一格失去前提。
   测试现在会检测窗口位移并**跳过**，而不是给出一个假的结论。

## 第 3 条怎么变成确定性的

原来靠 SuYou 做对照：截图 → 外部点一下切页 → 用旧候选点。三个不确定源全在环境里
（窗口会被移动、页面状态、实时数字），所以它经常只能跳过。

现在改成 `tools/fixtures/recheck-window.ps1` 造一个**自己会变脸**的窗口：

```
0.0s  窗口出现，显示 ALPHA-ONE
      截图 → 取候选（ALPHA-ONE）
2.5s  窗口自己把文字改成 BETA-TWO（窗口没动、几何完全一致）
3.2s  用旧候选点 → 拒绝「那块区域的内容已经变了」，不发送任何输入
      重新截图 → 取候选（BETA-TWO）→ 点得动（正向对照）
```

三个断言，零依赖环境状态。

顺带一个坑：这个 fixture 必须 **TopMost**。截图是 `CopyFromScreen` 抓窗口矩形那块**屏幕**，
窗口被别的窗口盖住时抓到的是别人的像素 —— 第一次跑就把 DSH 的日志文字 OCR 出来了，
而失败信息看起来像"候选里没有 ALPHA-ONE"。

# 鼠标卡在按下状态（用户实测）与三层兜底

用户报：鼠标黏在 SuYou 上，能拖着动。那是**左键处于按下状态没抬起来**。

## 成因

`SendMouseButton` 的每一次点击是：

```
mouse_event(DOWN) → Sleep(40ms) → mouse_event(UP)
```

如果进程在 DOWN 与 UP 之间**被 TerminateProcess 杀掉**，UP 永远不执行，
而 Windows 不会替谁松开鼠标。宿主的超时兜底正是 `child.kill()` —— 这条路径真实存在。

## 三层兜底（都实现了）

| 层 | 做法 | 覆盖哪类死亡 |
|---|---|---|
| helper 记账 | 按下置位、抬起清位；`ProcessExit` 里把**我们自己按下的**键抬起 | 正常退出、未处理异常退出 |
| 插件补发 | `runHelper` 超时分支杀掉子进程后，补发一次 `dsc.exe release` | 被强杀（收不到 ProcessExit） |
| 语义 | 只能松开记着的键；补发 release 会连用户自己按的键一起松开 —— 这一点写进错误文本，不隐瞒 | — |

代价写在代码注释里：鼠标只有一个，把卡住的键松开，比让用户拖不了东西更可接受。
另外，补发只放在**超时**路径上 —— `hold` 是故意按住不放的，每次都补会把正常按住打断。

# 测试里踩到的三个坑（都像功能坏了，其实不是）

1. **OCR 把 I 读成方块**：`CLICKHERE` → `C L □ C K H E R E`，于是没取到候选。
   夹具改用 `BUTTON`（只用笔画粗的字母）。换成 26 号 Consolas 也没用 —— 是字形问题不是字号问题。
2. **截图抓到别人的像素**：`CopyFromScreen` 抓的是窗口矩形那块**屏幕**，窗口被盖住就抓到上层窗口。
   夹具必须 `TopMost`；第一次跑就把 DSH 自己的日志文字 OCR 出来了。
3. **销毁截图目录不能制造观察失败**：候选的 PNG 就在那个目录里，会先报文件不在了。
   要造"点了之后看不到结果"，得让**窗口自己消失**（`closing-window.ps1`）。

# 第三批：复查的基线改成"屏幕对屏幕"，以及一次没查清的异常

## 改了什么

| 位置 | 改动 | 理由 |
|---|---|---|
| `desktop_visual_candidates` | 列候选时对**每个候选的复查区域**抓一次屏幕指纹，随候选存下 | 详见下面的异常 |
| `desktop_click_candidate` | 点击前抓一次屏幕，和那份**屏幕基线**比；不再拿截图裁出来的指纹当基线 | 两边必须同源 |
| 两边共用 `visualRoi()` | 基线区域 = 点击复查区域（都是"候选框 + 4px 余量"） | 踩过：基线用无余量的框、点击用带余量的框，两块像素根本不同，于是好端端的点击被判"内容已经变了" |
| 错误码 | 观察失效统一报 `失败：StaleObservation`（借 WebDriver 的 stale element 命名） | "该重新观察"和"该修环境"是两件事，不能都说成"找不到文件" |
| 急停 | `desktop_visual_candidates` 入口 + OCR 之后各查一次闸门 | 它不经过 helper，之前**按了 ESC 照样 OCR 旧图、照样返回界面文字** —— 这是真漏洞 |
| 列表上限 | 24 → 12 | 每个候选多一次抓屏（30~50ms），不能让列一次候选慢到几秒 |

## 那个没查清的异常（留着，不假装解决了）

现象：**同一块像素**，两种算法给出不同指纹。

```
A = image_hash(整张截图 PNG, 区域 54,122 171x34)         = ce0f8519841ee66a
B = image_hash(同一块单独存的 PNG, 0,0 171x34)           = f3c585f08d4d2c6c
   而 PIL 逐像素比对这两份图：diff bbox = None（完全相同）
```

整窗比对永远一致（rect 就是整图），**只有局部区域**会错。逐条排除过：

- 鼠标光标（把光标移出区域 → 指纹不变）
- `DrawImage(src, dest, srcRect, Pixel)` 的插值/半像素偏移（改 `Clone` → 不变）
- `LockBits(rect)` 的行跨度（改成锁整图 + 手工偏移 → 不变）
- PNG 往返（抓屏 → 存 PNG → 读回 → 算 → 不变）
- 用 PowerShell 独立抓同一块区域（与截图 PNG 逐像素相同）

**根因仍未钉死。** 结论是"从截图里裁出来算"这条路在本机不可靠，所以复查基线改从
屏幕取，两边同源。`image_hash` 保留，只作为老候选的兜底（并接受它可能误拒）。

## 主动放弃的一件事：动画检测

原计划借 Playwright 的 **Stable** 检查：同一块区域抓三次、间隔 200ms，全一样才点。
**实测不可靠** —— 夹具每 60ms 翻一次字，三次采样仍然能返回同一个指纹
（怀疑是 WinForms 计时器在 `DoEvents` 循环里的实际节拍远慢于 `Interval`，未证实）。

一个"看起来在检测动画、实际经常漏"的机制比没有更危险：后面的人会以为"在动的东西点不下去"。
所以只保留**一次采样**，并在文档里写明限制：**动画/过渡期间采样，可能被当成没有变化**。

## 现在的保证与不保证

- 保证：从**列候选**到**点击**之间，候选那一小块变过 → 拒绝，不发送输入。
- 保证：观察过期/属别处/被作废 → `StaleObservation`，且不会算出坐标。
- 保证：急停时连"读旧图"都不做。
- 不保证：截图那一刻到现在之间的变化（被"列候选时的基线"覆盖掉了）；
- 不保证：动画中途；不保证：候选区域**之外**的变化（那是刻意的：邻居在变不该殃及本目标）。

# 第四批：验收第 7、8 条（失败面 + 打包位置）

## 第 7 条：视觉后端的失败必须有界

**做法**：给 `ocr-worker.mjs` 留两个测试钩子（`DSC_POWERSHELL`、`DSC_OCR_SCRIPT`），
把正常机器上根本复现不出来的四种坏情况逼出来跑一遍。
理由很直接：**复现不了就等于没验证**。

| 场景 | 怎么造的 | 结果 |
|---|---|---|
| 脚本不见了 | `DSC_OCR_SCRIPT` 指向不存在的文件 | `NoOcrScript` → 工具返回"视觉后端不可用" |
| 解释器不见了 | `DSC_POWERSHELL` 指向不存在的 exe | `probeOcr` 语言列表为空 → "不可用" |
| 输出不是 JSON | 让 PowerShell 打印一行垃圾 | `BadJson`（含前 300 字符原文），不是抛栈 |
| 卡死 | 脚本睡 5 秒，超时设 800ms | `Timeout`，**1155ms 内返回** |

每种情况都额外断言两件事：**没有异常穿透到宿主**（返回的是一段说明）、
**`desktop_list_windows` 仍然可用**（插件整体没被拖垮）。

顺带修的两处：

- 超时原来被翻译成 `Spawn: … ETIMEDOUT`，和"程序不存在"混在一起。现在单独报 `Timeout`。
- `runOcr` 现在**先检查脚本是否存在**，不存在直接说 `NoOcrScript`，
  而不是让 PowerShell 报一个含糊的文件错误再被我们翻译成"执行失败"。
