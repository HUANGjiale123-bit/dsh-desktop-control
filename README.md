# dsh-desktop-control

> 给 DeepSeek Harness 的桌面操控能力：读无障碍树、截图、点击、输入。
>
> **这会让 AI 操作你的真实鼠标和键盘。装之前请读完「风险」一节。**

状态：**设计与环境验证阶段，尚无可用实现。**

---

## 这是什么

一个 DSH 插件，让 agent 能够观察并操作 Windows 原生桌面应用：

- 读取窗口的无障碍（UI Automation）树，以文本形式交给模型
- 截取窗口画面
- 在指定窗口内点击、输入文字、发送组合键、滚动

它不是一个新的自动化框架，而是**照 OpenAI Codex 的 Computer Use 架构重做一遍本地实现**（见 `docs/`）。

## 为什么这么设计

Windows 上的桌面自动化容易踩两个坑，这个项目专门绕开它们：

**坑一：坐标空间不一致。**
UI Automation 返回的元素矩形可能是**物理像素**，而截图与像素校验可能按**逻辑像素**工作。在 125%/150% 这类缩放设置下，两者差一个比例，于是"读到的位置"和"点的位置"对不上，屏幕上任何变动都会让校验永久失败。

**坑二：元素寻址的类型细节。**
用 `PropertyCondition` 批量查元素时，某些属性要求特定数组类型，传错就抛异常，且错误信息不含上下文。

本项目的做法是：

- **坐标空间单一**：抓屏、取树、注入输入由**同一个常驻原生进程**完成，坐标天然一致，不做换算
- **引用而非换算**：点击坐标必须声明"来自哪一张截图"（`screenshotId`），坐标空间被引用钉住
- **寻址用引用表**：不用 `PropertyCondition` 批量查找，改为遍历时记录元素的 `RuntimeId` 或直接持有 `IUIAutomationElement` 引用

## 架构

```
DSH 宿主进程
  └─ 插件（注册工具面）
       │  JSON 往返
       ▼
     常驻 helper 子进程  ←── 命名管道 ──→  插件
       ├─ 抓屏        → screenshots[] { id, dataUrl, filepath }
       ├─ 取无障碍树  → tree（字符串，元素 id 内嵌）
       └─ 注入输入    → 点击 / 输入 / 按键，同一套坐标
```

helper 必须常驻，因为要持有 `screenshotId → 坐标空间` 与 `elementId → 元素` 的映射。

**桌面访问权在 helper 那一层**，不在 agent 进程。这是这套设计能成立的前提。

## 风险

装这个插件等于给 agent 一双能操作你桌面的手。请明确知道：

- **它能点击、输入任何被允许的应用**，包括你的浏览器、聊天软件、文件管理器
- **截图会进入模型上下文** —— 屏幕上出现什么，模型就可能看到什么（含误入画面的密码、私信、余额）
- **无障碍树文本来自被操作的应用，属于不可信输入**。恶意页面或应用可能在文本里藏指令，诱导 agent 点危险位置（提示注入）
- **动作可能点错**：目标窗口可能已关闭、移位，或被别的窗口遮挡

因此本项目提供（见 `docs/设计.md` 的安全模型一节）：

- **应用白名单** —— 只有清单内的应用可被操作
- **逐动作审批** —— 走 DSH 官方审批接缝
- **ESC 物理急停** —— 随时掐断
- **不抢前台焦点** —— 默认不激活目标窗口，不打断你手头的操作
- **脱敏与审计** —— 树文本与路径进模型前截断掩码，动作写入会话日志

**不要在没有白名单和审批的情况下使用它。**
