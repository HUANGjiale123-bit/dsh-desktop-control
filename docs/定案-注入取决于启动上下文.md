# 定案：注入能力取决于启动上下文，与代码无关

**日期**：2026-10-14
**结论**：同一份二进制 `InjectSelfTest.exe`

| 启动方 | 起始光标 | SetCursorPos ×3 | SendInput 相对 | 结果 |
|---|---|---|---|---|
| Codex 的 shell | **(0,0)** | 全部 `ret=False` | `ret=0`，位移 0 | **0/3** |
| Codex 的 computer use helper（`launch_app`） | **(1574,1123)** | 全部 `ret=True`，精确命中 | `ret=1`，位移 (60,60) | **3/3** |
| 我的 shell（DSH 子进程） | (1059,1143) | 全部 `ret=False` | `ret=1`，位移 (0,0) | **0/3** |

**代码一行没改。唯一的变量是"谁启动它"。**

---

## 这推翻了本项目此前所有的归因

追查这一天的过程中，我给过很多解释，**全部是错的**：

| 我曾归因于 | 实际 |
|---|---|
| 我把鼠标代码改坏了（`SetCursorPos` vs `SendInput`） | ❌ 代码是对的 |
| 坐标空间 / DPI 问题 | ❌ 屏幕读数正确（2240x1400） |
| 进程在错误的桌面上 | ❌ `CompareObjectHandles` 判定同一对象 |
| AppContainer 沙箱 | ❌ 双方都是 0 |
| 完整性级别 / 提权 | ❌ 双方都是 ElevationType=3 |
| 作业对象 UI 限制 | ❌ `UIRestrictionsClass = 0` |
| `BlockInput` | ❌ 解除后仍无效 |
| 目标应用类型（Electron / 打包应用） | ❌ 同一目标窗口，换上下文就能用 |
| 合成前台切换导致输入被压制 | ❌ 是表象之一，不是根因 |
| 读 `SetCursorPos` 的 last-error | ✅ **这条是真错**（该 API 不设置 last-error） |
| 用返回值当判据 | ✅ **这条是真错**（应读光标实际位置） |

**最后两条是我真正的错误，但它们是"测量方法的错误"，不是"根因"。**

## 已知的事实

**能注入的上下文**：Codex 的 computer use helper（`codex-computer-use.exe`）
**不能注入的上下文**：任何 shell 进程（Codex 的、我的都是）

Codex 自己的解释：

> Computer Use 能真的移动鼠标，是因为它的 helper（`codex-computer-use.exe`）
> 是**独立进程，不在我这个 shell 的沙箱里**。

**关键旁证**：不能注入的那些 shell，光标读数是 `(0,0)` 或读得到真实值——
两种都有，**但都不能注入**。所以"能读到光标"不等于"能注入"。

## 那个"受限上下文"具体是什么：未知

所有能查的字段都显示进程是正常的：

```
AppContainer      = 0
ElevationType     = 3 (Limited，UAC 过滤令牌的常态)
会话               = 44
窗口站 / 桌面      = WinSta0 / Default
作业对象 UI 限制   = 0x00000000
```

**没有一个字段体现这个限制。** 我不再猜——这一天的代价已经证明了"猜"的代价。

**候选（均未验证）**：
- 某种不体现在令牌字段里的隔离（例如 Codex 侧提到的 shell 沙箱）
- 输入队列的归属异常（钩子链能看到物理键，但合成输入被丢弃）
- 注入需要进程与目标同属某个"输入会话上下文"，而 shell 不属于

## 对项目的实际影响

**这套工具要在能注入的上下文里运行才完整。** 具体地：

| 环境 | 读（窗口/树/截图） | 写（set_value / do_action，走 UIA） | 注入（鼠标/键盘） |
|---|---|---|---|
| 普通用户会话（双击启动） | ✅ | ✅ | ✅ 预期可用 |
| Codex 的 computer use helper | ✅ | ✅ | ✅ **已实测 3/3** |
| 从 agent 的 shell 启动 | ✅ | ✅ | ❌ **实测 0/3** |

**关键推论**：如果用户从**普通的命令提示符或快捷方式**启动 DSH，
那么它的子进程（我的 helper）应当也能注入——**这一点尚未验证**，
但它是最容易做、也最可能一次性解决的验证。
