# 截图坐标契约：多条件验证矩阵（2.18.32）

> 一句话：把"旧截图还能不能用"的七种情况逐一跑了一遍，
> 发现两处真的会咬人的地方（都修了），另外补上了过期那条的验收手段。

## 为什么这件事值得单做

`shotId` 这条链有三层校验，判据各不相同：

| 层 | 检查什么 | 失败的样子 |
|---|---|---|
| 插件 `checkShot` | 记录存在 / hwnd 一致 / 有几何 / 未过期 | "找不到截图"/"太久无法保证" |
| `toolset.click` | 尺寸变了拒绝；位置变了看坐标空间 | "窗口尺寸变了"/"窗口一移就不点" |
| helper `click` | `WindowFromPoint` 判落点属于谁 | "不是指定的目标窗口……不会替你去点" |

任何一层松一点，表现都是**点击照常发出、照常报成功，但落点已经不是原来那个东西**。
这类错误在本项目里最贵：失败不报错。

## 矩阵与结果

测试：`tools/test-shot-matrix.mjs`（真的移动/缩放/遮挡用户的窗口，`finally` 里复原）
与 `tools/test-shot-ttl.mjs`。靶子：SuYou（Tauri，688x1055 @1242,113）。

| # | 条件 | 期望 | 结果 |
|---|---|---|---|
| 0 | 正常截图 | 拿到 shotId | ✓ |
| 1 | 窗口移动 + `space=desktop` | 拒绝并说明原因 | ✓ "窗口一移这个坐标就指向别处了，所以不点" |
| 1b | **被拒绝之后**同一个 shotId | 仍然有效 | ✓（这一格是新发现的 bug，见下） |
| 2 | 窗口移动 + `space=window` | 放行 + 警告 | 几何校验已放行；注入被沙箱拦（`SetCursorPos` 错误 5），警告文本看不到 |
| 3 | 窗口改大小 | 拒绝 | ✓ "尺寸变了，旧坐标不可靠" |
| 4 | shotId 属于别的窗口 | 拒绝 | ✓ "两个窗口的坐标不能混用" |
| 5 | 落点被置顶窗口盖住 | 拒绝，且不去点遮挡者 | ✓ "不会替你去点那个盖住它的窗口" |

`test-shot-matrix.mjs`：6 项通过 / 3 项跳过；`test-shot-ttl.mjs`：2 项通过。
全套 29 个测试文件全绿。

## 修掉的两处

### 一、被拒绝的动作不该作废截图 —— 它让插件自己的建议走不通

原来只要调用了变更性工具，收尾 `finally` 里一律把动作前的截图作废，
**连"被拒绝、什么都没发生"也作废**。于是出现这样一段自相矛盾的对话：

```
插件：窗口移了……你可以改用 space="window"（原点按当前矩形算），或者重新截图
调用方：改用 space="window" 重试
插件：找不到截图记录
```

建议本身依赖的正是刚被烧掉的那个 shotId。第三方复核没看到，因为单看任何一个功能都正常。

修法：按"有没有可能已经产生输入"分类。各命令都是**先校验、后注入**，
所以下面这些错误码可以确定什么都没发生 —— 保留旧观察：

`Halted` `NotAuthorized` `WhitelistEmpty` `HelperMissing` `Busy` `Cancelled`
`Refused` `StaleTarget` `StaleSnapshot` `NotFound` `AmbiguousTarget`
`BadValue` `BadIndex` `BadAction` `OutOfRange` `ActionNotAvailable`
`NotSettable` `RangeUnavailable` `ReadOnly`

其余（`Timeout`、`UnknownOutcome`、未知错误）一律当作"可能已经动过"，照旧作废 ——
宁可多作废一次（代价是重截一张图），也不要在布局可能变了之后拿旧坐标继续点。

### 二、几何拒绝的消息没有机器可读的码

第一处修完之后，"窗口移了"这一格仍然在作废截图 —— 因为这条拒绝的文案是
`失败：截图拍摄时窗口在 (…)，现在在 (…)`，而 `guessErrorCode` 只认
`失败：<英文码>` 这种形状，于是它被归成 `Error`（未知），按保守策略作废。

现在两条几何拒绝都带上了码：

```
失败：StaleSnapshot — 截图拍摄时窗口在 (1242,113)，现在在 (1302,153)。
你用的是 space="desktop"……所以不点。
```

顺带把 `Refused` 的提示补全了：它背后其实是四种完全不同的原因
（白名单 / 闸门 / 落点被盖 / 光标移不过去），旧提示只列了三种。

### 顺带：给保鲜期留了一个验收开关

`DSC_SHOT_TTL_MS` 可以覆盖默认的 5 分钟。唯一的正当理由是测试 ——
"过期必须被拒绝"这条只有等 5 分钟才能触发，那等于没人验。
（和 `DSC_HALT_TTL_SECONDS`、`DSC_PYTHON`、`DSC_HELPER` 是同一类开关。）

## 测试自己踩的两个坑（都写进注释了）

1. **`SetWindowPos` 在 DPI 未感知的 PowerShell 里会被放大 1.5 倍。**
   这台机器是 150%，于是"把窗口移到 (1302,153)、尺寸 688x1055"实际得到
   `1033x1583 @(1863,170)`，测试格子报的是"尺寸变了" —— 校验没错，是我给的数不可信。
   和桥里那个 DPI 坑是同一个，所以现在所有几何脚本都先
   `SetProcessDpiAwarenessContext(-4)`。

2. **`windowsHide: true` 会让进程的**第一个窗口**也变隐藏。**
   遮挡窗口（一个无边框 WinForms 窗体）创建成功、`Visible=True`，
   但 `WindowFromPoint` 在屏幕上找不到它 —— 连事后 `ShowWindow(SW_SHOWNORMAL)`
   也救不回来。`detached: true` 同样起不来。表现是"遮挡没生效，这一格跳过"，
   查了两轮才定位到 spawn 参数。

   另外：`ShowInTaskbar=$false` 的窗体不会出现在 `dsc.exe list_windows` 里
   （被当工具窗口过滤），所以判断"盖住了没有"用的是 `WindowFromPoint`，
   和 helper 判落点用的是同一个 API —— 这比看窗口列表更接近真实判据。

## 还没覆盖的

- **窗口被关掉 → `StaleTarget`**：需要关掉一个真实应用，收益不抵代价；没验。
- `space=window` 那条的**警告文本**：几何校验确实放行了（走到了注入），
  但这台机器的沙箱拦下 `SetCursorPos`，成功路径的文案没出现 —— 属于取样环境，不是代码。
- 多显示器、跨 DPI 拖动窗口（窗口从 100% 屏拖到 150% 屏）没验。
