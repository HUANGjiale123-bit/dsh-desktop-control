# dsh-desktop-control —— 唯一入口文档

> 版本 **2.18.52**。给 Windows 桌面做观察与操作的 DSH 插件（25 个工具 + 2 个辅助可执行文件）。
> 这份文档是**起点**：先读它，需要细节再跳转到文末索引里的专题文件。

---

## 1. 它是什么

插件把 Windows 桌面变成模型能用的工具：列窗口、读无障碍树、截图、按名字点、按坐标点、
输入文字、滚轮、拖拽、视觉候选（OCR）、裁图放大。

设计上的三条底线，任何改动都不能破：

1. **看不清就别点**——所有点击前都会核对窗口几何与落点归属，不确定就拒绝并说明原因。
2. **拒绝要说人话**——区分"该重新观察"、"该修环境"、"用户叫停了"这三种失败。
3. **急停必须真的停**——ESC 闸门由 helper 和桥各自检查，插件不缓存豁免。

## 2. 30 秒上手

```yaml
# profile patch
- id: desktop-control
  name: dsh-desktop-control
  config:
    allowedApps: ["notepad.exe", "mspaint.exe"]   # 空 = 什么都不放行
    # helperPath: "D:\\path\\to\\dsc.exe"          # 可选
    # shotDir:    "D:\\path\\to\\shots"            # 可选
```

- 第一次读/点某个应用会**弹授权**，按会话有效。
- 按 **ESC** 立刻拦下所有操作；恢复只有一条：`dsc.exe stop --clear`（或重启会话）。
- 装好后先跑 `desktop_diagnose`：它会把 DPI、闸门、helper 完整性一次说清。

## 3. 工具地图：什么时候用哪个

| 你在干什么 | 用这个 | 什么时候换 |
|---|---|---|
| 看这个窗口里有什么 | `desktop_read_window` | 树信息很少 → 先 `desktop_screenshot` 看画面 |
| 点一个看得见名字的按钮 | `desktop_click_element` | 找不到名字 → 坐标点或视觉候选 |
| 输入文字 | `desktop_set_value`（输入框）→ `desktop_type` | 输入框不认就 `desktop_type` |
| 没有名字的目标（画布/自绘/残树） | `desktop_visual_candidates` → `desktop_click_candidate` | 目标很小 → 先 `desktop_visual_view` 放大，再按 `(u,v)` 报点 |
| 任何"点之前想确认"的场合 | `desktop_whatis` | — |
| 快捷键/组合键 | `desktop_press_key`（支持 F1~F24） | — |
| 滚动 | `desktop_wheel` | — |
| 拖文件/调整窗口 | `desktop_drag` | — |

**判断规则**（这段同时以系统提示的形式随插件注册，见 `plugin/index.mjs`）：
能按名字点就别用坐标；树读不到才走视觉；截图被遮挡时先激活再截；不确定生效没生效就重新观察，
不要对同一位置重复点击。

## 4. 三条契约

### 坐标

| 空间 | 谁在用 | 含义 |
|---|---|---|
| `desktop` | `desktop_click`、`desktop_drag` | 桌面绝对物理像素 |
| `window` | `desktop_click(space:'window')` | 窗口内像素（图内坐标 + 窗口原点由插件加） |
| `(u,v)` | `desktop_click_candidate(viewId, point)` | **放大裁图内**的比例，左上 (0,0)、右下 (1,1) |

只有两条换算函数：`candidatePointToWindow()`（整图点 → 窗口）和
`viewPointToWindow()`（裁图内 u/v → 窗口）。**不允许在别处再做换算**。

### 证据

每次截图都登记：`shotId`、窗口几何、图片真实尺寸（解码 PNG 头）、`sha256`、所属会话、代次。
读取时重算 `sha256` 并与登记值比对。点击前做**逐像素复查**（每通道容差 2），
不一致就拒绝，一个字节的输入都不发。

### 失效

一张截图在下列时刻作废：被新截图挤出（上限 24）、动作改变布局、超过 TTL（默认 5 分钟）、
换会话、撤权。作废会**级联**清掉它的视图与候选。

## 5. 安全模型

- **白名单**：`allowedApps` 为空 = 什么都不放行。会话内授权单独记录，会话结束即撤销。
- **急停**：ESC 写一个闸门文件；`dsc.exe` 的每条命令、桥的每次点击前都查它。
  闸门拉着时所有变更操作被拒，且提示"不要自己解除"。
- **按键不卡住**：`mouse_event(DOWN)` 与 UP 之间进程若被杀，鼠标会黏住。
  三层兜底——helper 记账 + `ProcessExit`、插件在超时后补发 `release`。
- **不做静默重试**：点击发出后结果未知时只报告不确定，绝不自动再点一次。

## 6. 已知限制（都实测过，不是推测）

| 限制 | 说明 |
|---|---|
| 目标 < 8px | 直接拒（`TargetTooSmall`）——放大只是把糊块变大 |
| 遮挡 | 截图抓的是屏幕上那块；被盖住时抓到覆盖者（工具会警告，先激活再截） |
| 动画 | 复查只采样一次；动画期间的采样可能被当成"没变"（已放弃通用动画检测） |
| 图标 | OCR 只认文字；纯图标目标视觉路径**无能为力** |
| 多屏/跨 DPI | **未实测**（只有一块屏） |
| 100% 缩放 | **未实测**（本机 125%） |
| UWP/WinUI 残树 | 无解（cua 的 root-walk 在本机取到 0 个节点） |
| Chromium | 需要 UIA 桥，且 helper 必须是 Medium 完整性（工作区带 Low 标签时会退化） |

## 8. 出问题先看哪儿

| 现象 | 先看 |
|---|---|
| 工具全部消失 | 插件加载失败 → 宿主日志；多半是文件缺失（`run-all` 里的 `test-packaged-install` 会抓） |
| 点了没反应 | `desktop_diagnose`（DPI/闸门/完整性），再看 `desktop_whatis` 落点是谁 |
| 一直说"内容变了" | 看 `trace.jsonl` 里 `recheck.diffPixels/maxDelta`；多半是目标附近有实时数字 |
| 急停后恢复不了 | `dsc.exe stop --clear`（闸门由人清，模型不应自己清） |

trace 位置：`<shotDir>/trace.jsonl`（JSON Lines，2MB 轮转，含 before/after 图片路径、落点、复查结果）。
