# 对外汇报 v2.18.64：把光标替换做成可用功能

> 上一份（2.18.51）之后的工作全部集中在一件事：**让"光标变成画里的鲸鱼"从想法变成
> 可发布的功能**。这条路上踩了四个坑、推翻过自己的两个结论，都记在这里。
> 仍然没有做的部分在最后，没有假装做过。

---

## 0. 一句话

系统级光标替换已可用：15 个标准光标全部透明，由叠加层按**系统真实光标槽位**绘制
对应形状（箭头/I 形/手形/加载圈/四向/双向），配看门狗与旧系统自动降级；
空闲时占用 0.78% 单核。**只在一台机器（150% DPI、单屏）上验证过。**

---

## 1. 为什么不是"叠一层图"那么简单

Windows 的鼠标指针由系统单独合成，**永远画在所有窗口之上**。所以：

- 叠加层只能垫在光标**下面**——素材里若自带箭头，会和真箭头叠成"双箭头"
- 真正替换只有 `SetSystemCursor`（改系统全局资源）

素材共两批：
- **A 批**（10 张 + 2 张命名图）：透明背景，**画里自带箭头**——系统箭头透明后，
  画里的箭头就是指针
- **B 批**（10 张）：透明背景，**没有箭头**，只能当"旁边的装饰"

最终用 A 批做透明光标，B 批保留为装饰模式的素材。

## 2. 四个坑（按发现顺序）

### 坑一：句柄跨进程不可比

想用 `GetCursorInfo` 的句柄判断"当前是哪种光标"，实测：

```
标准箭头：我这边 LoadCursor 得到 65539，系统当前光标是 65543 → 不同
```

**同一个标准光标在不同进程/DPI 上下文里句柄值不同**，句柄比较这条路直接断。

### 坑二：全透明之后，形状信息也没了

把 15 个槽位都换成同一张空白后，屏幕上看不出区别，也读不回来——**"当前是哪个槽位"
的信息被我们自己抹掉了**。

### 坑三：透明掩码会连 alpha 一起丢掉

第一版"隐形记号"（alpha=1 的红点）读回来是 `maxAlpha=0`。原因：**AND 掩码全 1
（透明）时，GDI 根本不用颜色位图**。把记号那一像素的掩码位改成"不透明"，
alpha=24 的红点才被画出来，且人眼看不见。

### 坑四：`--watch … blank` 的 `blank` 不是 `--blank`

常驻模式里漏了一个赋值，导致 `followCursor` 恒为 false，走到"按插件写的 fx.pose 选图"
的分支——**形状永远不变**。用户当时说的"图没跟着变"，一半是设计问题，一半是这条 bug。

## 3. 最终机制

```
① 15 个槽位各装一张"带隐形记号"的空白光标
   第 i 个槽位的记号在 (i*2, 0)，alpha=24，掩码位=不透明
② 每 150ms：DrawIconEx 把当前光标画进 48×48 位图 → 查 15 个记号像素 → 槽位号
③ 槽位 → 素材映射（IBEAM→I 形、HAND→手形、WAIT→加载圈、SIZEALL→四向…）
④ 应用私有光标（没有记号）→ 隐藏我们的图，让系统光标显示，避免双光标
⑤ 恢复：SPI_SETCURSORS（幂等，从不写注册表）
```

实测识别（全透明状态下）：

| 位置 | 识别 |
|---|---|
| 侧边栏 | HAND |
| 标题栏（流式输出中） | APPSTARTING |
| 输入框 | IBEAM |
| 消息区 | ARROW |

## 4. 安全：三道恢复 + 自动降级

| 路径 | 做法 |
|---|---|
| 正常退出 | 进程退出路径调 `SPI_SETCURSORS` |
| 插件卸载 | 写 `fx.stop`，看门狗随后退出 |
| **进程被强杀** | `dsc-guard.exe` 每 400ms 看 `fx.blanked` 里的 PID，死了就恢复（实测 470ms） |
| 旧系统 | `SetWindowDisplayAffinity` 失败或 build < 19041 → **不启用**，写 `degraded` 日志后退出 |

降级这条是必须的：`WDA_EXCLUDEFROMCAPTURE` 在旧系统上**静默失败**，
鱼会被拍进截图 → 像素复查全线误判 → 比没有装饰严重得多。

## 5. 性能（这条是量出来的，不是猜的）

| 阶段 | 单核 | 全机 |
|---|---|---|
| 每帧识别 | 5.9% | 0.37% |
| 时间降频 + 去抖 | 3.36% | 0.21% |
| **三级休眠** | **0.78%** | **0.049%** |

关键发现：**开销不在单次调用，而在帧率本身**。剖析显示循环体每帧只有 0.2ms，
但静止时每秒 20 帧、每帧都是"便宜但不免费"的系统调用。

另外，识别结果会**抖动**（静止时光标槽位在 12/1/11/0 之间跳），每跳一次就重绘 +
写日志。去抖（连续两次一致才切换）后，`draws` 从 41/100 帧降到 2/200 帧。

## 6. 打包 bug（发布前抓到）

2.18.63 的 tgz 里**只有 1 张光标素材**——`package.json` 的 `files` 没写
`assets/cursor/poses-arrow`。npm 只打它被告诉的东西，**少了也不报错**。
朋友装上会得到"功能静默失效"的插件。

已修（23 个素材条目），并加了回归测试：遍历 `plugin/assets`，任何文件不在 `files`
清单里就失败。反向验证过（删掉条目 → 报 11 个缺失）。

## 8. 想请评审看的四点

1. **默认为关**是否合适？（现在装完是关的，用户要显式打开）
2. **隐形记号**这个方案有没有更稳的替代？（比如直接分析光标位图与标准光标做匹配）
3. **降级判据**是否足够：现在用 `SetWindowDisplayAffinity` 返回值 + build 号，
   有没有更直接的"自测截图排除是否生效"的办法？
4. **看门狗**只覆盖"进程死了"这一种；如果恢复调用本身失败（权限收走、会话切换），
   还能怎么办？
