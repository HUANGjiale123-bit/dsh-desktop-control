## 1. 这是什么

一个 **DSH（DeepSeek Harness）插件**，让模型能观察和操作 Windows 桌面：
截图、读无障碍树、点击、输入、拖动、滚轮。

和常见 computer-use 实现的区别在于**安全模型**：应用白名单（默认空）、
会话级授权（每次操作弹窗问用户）、物理 ESC 急停、屏幕上常驻指示层。

作者不是专业 Windows 开发者 —— 这份文档里所有"实测"都是真机跑出来的，
但**很多结论只在两台机器、单屏、100% 缩放下成立**。

## 2. 架构

三层，每层职责明确：

```
plugin/index.mjs      工具注册、指示层、截图登记、执行权(lease)、trace
      ↓
server/toolset.mjs    授权、坐标换算、helper 调用、错误分类
      ↓
helper/src/Program.cs dsc.exe —— 真正的 UIA 与输入注入（C#，C# 5）
```

`plugin/` 下的 `toolset.mjs` / `tooldsl.mjs` / `apps.mjs` 是 `server/` 的**拷贝**，
由 `tools/sync-plugin.sh` 同步。两份是为了让同一份逻辑既能做插件、也能做 MCP 服务器。

**为什么 helper 是独立进程**：注入需要 `SetProcessDPIAware` / 清单指定的
PerMonitorV2，而这些必须是进程启动时定的。插件进程由宿主决定，改不了。

## 3. 做了什么

### 3.1 观察

| 工具 | 说明 |
|---|---|
| `desktop_screenshot` | 返回图片 + **坐标元数据**（原点/尺寸）+ `shotId` + 遮挡检测 |
| `desktop_read_window` | UIA 树；剪枝、共享预算、时间上限 |
| `desktop_whatis` | **某个坐标处是哪个元素** —— 点之前先问 |
| `desktop_list_windows` | 窗口列表（**不含标题**，避免泄露内容） |
| `desktop_list_apps` | 已安装应用 |
| `desktop_diagnose` | 状态诊断；`{perf:true}` 看性能 |

### 3.2 操作（21 个工具）

单击（左/右/中、`count:2` 双击）、描述符点击（优先 InvokePattern）、
Unicode 输入（每 16 字符查急停）、按键、`set_value`、`do_action`、
悬停、直线拖动、**路径拖动**、滚轮（纵/横）、**hold/release**、启动应用。

### 3.3 安全

```
· 应用白名单，默认空 —— 未授权时一律拒绝
· ESC 急停：闸门文件 + 60 秒自动恢复（DSC_HALT_TTL_SECONDS=0 可关）
· 指示层：光带 + 逃生条，变更性操作自动拉起，8 秒空闲收起
         收起只杀进程，**不写闸门**（收界面 ≠ 停止）
· 执行权 lease：同一时刻一个操作；拿不到 8 秒后明确拒绝
· hold 残留：磁盘记录 + 启动时自动松手
· AppContainer 自检：沙箱内禁止注入，直接拒绝
```

### 3.4 正确性

**shotId 契约**（核心设计）

```
截图 → shotId + 几何元数据
点击时校验：窗口没移、没改大小、TTL 内
记录里带 evidence: 'geometry_only'
  → 明确标注"只能证明到这个程度，不能证明画面没变"
```

**失效统一**：11 个变更性工具，执行后（**含失败**）一律作废该窗口的旧截图。

**错误事实 + 恢复建议**（15 个 helper 码 + toolset 手写 + index 层全覆盖）

```
失败：StaleTarget — 目标窗口 1 不存在或已关闭...
  [retry=reobserve] 目标窗口没了，重新列窗口，别用旧句柄
```

五种 `retry`：`stop` / `reobserve` / `wait` / `disambiguate` / `giveUp`。
未知错误默认 `reobserve`（唯一不可能更糟的动作）。

### 3.5 性能

```
· tracing：AsyncLocalStorage，并发三次不串号（实测）
· perf 视图：total / helper.* / auth 分开；p95 样本 <5 时不编造
· 截图清理：40 张 + 6 小时（实测 67 个/33MB → 40 个/8.2MB）
```

**第一个跑出来的数字**：`total ≈ helper`（80.9 vs 80.6 ms）——
工具层开销可忽略，时间全在**起进程**。

## 4. 想做的

### P0

**① 授权按会话分**
现在 `grants` 是插件单例里的全局 Map。会话 A 授权的应用，**会话 B 直接用**。
急停保持桌面级（用户按 ESC 时不知道是哪个会话），但**授权可以精确到会话**。

**② 执行前目标重验**
动作前重新解析 UIA 目标、确认唯一、确认可操作状态。
不依赖捕获后端，比像素比对便宜。

**③ lease 的真实并发验证**
17 项单元测试通过，但**两个真实会话抢锁没验过**（一次只能调一个工具）。

### P1

**④ 多屏 / 125%~200% DPI** —— 只有一块屏。
**⑤ 像素核验** —— 需要原始像素 + 误放行率实测，现在只有 PNG。

## 5. 我认为**不该**做的（请挑战）

| 项 | 我的理由 | 可能在什么条件下我错了 |
|---|---|---|
| **常驻 helper + IPC** | 实测比值 1:360（helper 60ms vs 模型一轮 40s），不是瓶颈 | 如果将来做**高频轮询**（每秒多次取状态），60ms×N 才浮现 |
| **WGC 截图** | 需要 Windows SDK，大概率要迁项目结构 | 如果需要**抓被遮挡窗口**，GDI 的 `CopyFromScreen` 做不到 |
| **统一观察对象重构**（epoch/observationId/elementRef） | `shotId` 已覆盖主要场景 | 如果需要"跨多个动作的事务级一致性" |
| **像素比对（现阶段）** | 成本没测过，误放行率没数据 | 如果用户能提供**可复现的测试场景**给出数据 |
| **模型能力基准** | 那要跨模型对比，我只能测自己 | 如果有多模型环境 |
| **跨进程 lease** | 显式单控制器限制够用 | 如果用户真的开两个 DSH 进程同时用 |

## 6. 我判断不确定的地方

这几处我拿不准，**特别希望被指出**：

### 6.1 急停的 TTL 该多长

现在是 **60 秒**。依据是"我的一轮操作 30-60 秒，足够打断"。

用户的反馈是："有时候只是临时看到你做错了，想和你说一下，只要任务中止后，
你没继续在干活就可以解除了"。

**但**：如果调用方在 60 秒后还在重试，那说明它没理解 —— 延长闸门能解决吗？
还是应该换一种信号机制（比如"必须在结果里确认收到停止信号"）？

### 6.2 执行权的粒度

现在：**整个工具调用**持锁。所以 `desktop_click` 从进到出独占，包括它的截图。

**问题**：`observeAfter` 里的截图在锁内 —— 这是对的吗？
它保证了"动作 + 它的观察"原子，但也让锁的持有时长从 100ms 变成 300ms。

### 6.3 错误分类的边界

`NotFound` 可能是：窗口关了（该 `reobserve`）、元素没渲染（该 `wait`）、
描述符写错（该 `disambiguate`）。

helper **不知道自己为什么被调用**，所以判不出来。现在统一给 `reobserve`。

**这个降级代价多大？** 有没有更好的做法？

### 6.4 DRY 与同步

`server/toolset.mjs` 和 `plugin/toolset.mjs` 是同一份内容的拷贝，
靠 `tools/sync-plugin.sh` 同步。**这是设计还是技术债？**

选择理由：插件要能独立打包（不能 `../server/` 引用）。

## 7. 已知限制（诚实清单）

```
· Electron / WinUI 内部完全不暴露 —— 只能坐标，而坐标是估的
  （实测：网易云 8 个节点、Chrome Legacy Window 一层）
· 拖窗口标题栏要找到"真正的"标题栏（标签栏可能盖在上面）
· 跨屏、非 100% DPI **完全未验证**
· 部分功能只有单元测试，无真实环境验证（见 4.3）
· 沙箱内的 helper 无法注入输入，也无法用 AutomationElement.FromPoint
  → 所有注入类验证都必须在"插件环境"里做，不能在开发沙箱里做
```

### 一个具体的失败模式

```
用户按 ESC 想暂停
→ 模型重试（因为动作被拒）
→ 每次授权成功都调 ensureIndicator() 拉起指示层
→ 蓝条反复出现，用户看到的是"它不听我的"
```

已修（`ensureIndicator` 检查闸门），但**这类"程序正确、体验错误"的问题
只有真机用才会暴露**。

## 8. 关键设计决策（供挑战）

| 决策 | 理由 |
|---|---|
| **图像必须以 attachment 进模型** | 文本描述是谎 —— 实测模型收到"空描述 + 真图像"时能正确回答 |
| **不可见时不做动作**（`SetForegroundWindow` 失败就拒绝点击） | 后台注入可以命中错误窗口 |
| **`click_element` 优先 InvokePattern** | 矩形中心在嵌套/滚动/遮挡时可能落到别的元素 |
| **急停只查闸门文件** | 不依赖插件存活 —— 插件崩了急停照样有效 |
| **指示层收起不写闸门** | "不再显示"和"停止"是两件事 |
| **错误消息里写 `[retry=...]`** | 传输层没有结构化错误通道，而模型读的是文本 |
