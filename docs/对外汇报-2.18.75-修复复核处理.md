# 2.18.75：对送审复核的收尾

> 对应上一轮送审后的复核报告。本文只写这一轮改了什么、怎么验的。

## 1. P1 原生光标恢复的两个分支（已修）

复核指出 `Fx.cs` 心跳停止分支与 inactive 分支仍会"恢复失败也删标记"，`Guard.cs` hostGone 失败后照样退出。

- fx 心跳停止：成功才清 `blanked`/标记；失败保留并 **2 秒退避后继续重试**，不再退出
- fx inactive：成功才清；失败保留标记、1 秒后重试
- guard hostGone：失败保留标记并继续循环（不再是"标记留着、人走了"）

## 2. P1 guard.ready 陈旧（已修）

- 插件每次启动生成 `runId`，同时传给 fx 与 guard
- guard 写 `{"runId":"...","pid":N}`
- fx 校验 **runId 匹配 + PID 存活**；运行中每秒复查，看门狗失效立即恢复系统光标并暂停隐藏
- 兼容旧格式（纯 PID），但必须是活进程

## 3. P2 恢复判定收紧（已修）

`r.ok === true && r.data?.ok === true`。`{}`、缺字段、`ok:null` 都算未确认。

## 4. P2 桥 Halted 协议（已修）

- PowerShell 急停分支输出 `{ok:false, error:"Halted", invoked:false}` 并 `return`
- Python 保留结构化错误
- toolset 映射成 `code=Halted`、`retry=stop`，不走坐标补点/NotFound 兜底

## 5. P2 诊断恢复命令（已修）

```
$env:DSC_HALT_GATE='<实际闸门>'; & '<实际 helperPath>' stop --clear
```

单引号转义、路径引用、helper 不再从 `escPath` 推导。

## 6. P2 测试与说明

- `test-clean-profile`：先移 bundle 引用再 remove，并断言卸载后 bundles 不含该插件（17/17）
- `test-cursor-failure`：失败分支改 `bad()`，统计真实启动尝试与 ENOENT（6/6）
- 说明：卸载等待分阶段（5 秒 + 最长 8 秒）；"25 秒""任何情况下"改为条件表述

## 7. 测试结果

全量 563 条断言，0 失败，4 项跳过；干净 profile 17/17；ready 判据 12/12。
