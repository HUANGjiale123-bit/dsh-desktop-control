# dsh-desktop-control 使用经验与技巧

> 这份是**给用这个插件的人（或 agent）看的实战笔记**，不是功能列表。
> 内容来自实际拿它做了几十次真实操作（建 GitHub 仓库、填表、传文件、修 DSH 自己的 bug）踩出来的。
> 版本：1.0.0。默认关闭光标装饰；下文会单独说。

---

## 0. 先记住一句话

**能按名字点，就不要按坐标点；能先看，就不要先动。**

这个插件的价值不在于"能点"，而在于**点之前会核对**：窗口、前台、完整性、落点归属、急停。
你要做的是顺着它的核对走，而不是绕过它。

---

## 1. 标准起手式

```
1. desktop_list_windows          看有哪些窗口（不含标题）
2. desktop_read_window 或 desktop_screenshot   看内容
3. desktop_click_element(...)    优先按名字点
4. desktop_screenshot            动作后复查
```

- `list_windows` 不需要授权、也不读内容，**永远先跑它**
- 有标题依赖时用 `read_window`（会先请求授权）
- 截图返回的是**图像**，可以直接看；`shotId` 留着给后续坐标点击用

---

## 2. 坐标相关的三个坑

1. **坐标是物理像素**，不是逻辑像素。150% 缩放下，你在截图预览里目测的坐标要先按
   `图宽 ÷ 实际像素宽` 换算，或者直接 `desktop_whatis` 核对。
2. **窗口有原点**。截图里的 `(ix, iy)` 对应桌面 `(originX + ix, originY + iy)`。
   插件会告诉你原点，别自己猜。
3. **点击前先 whatis**。返回"这里是什么元素"；点错了它只会"没反应"，不会报错。

> 经验：`desktop_click` 的返回里会带 `atElement`（落点上的元素）。**看这个字段**，
> 它比"成功"两个字有用得多。

---

## 3. 什么时候用按名字点（`click_element`）

优先用于：

- 原生控件（Win32 / WinForms / WPF）：记事本菜单、按钮、输入框
- Chromium 系（浏览器、DSH 自己、ChatGPT）：走 UIA 桥，能读到 39~60 个节点

**不适合**：

- 画布、游戏、自绘界面（读不到名字）
- 网页里没有无障碍名字的 div

浏览器场景的实战要点：

- 地址栏可以直接 `Ctrl+L` 然后 `desktop_type`
- 表单字段用**无障碍 name**定位，例如 `Repository name *`、`Description`
- 提交按钮通常支持 `InvokePattern`，**不需要移动鼠标**，比坐标点可靠
- 名字写错时，错误信息会列出"同一范围里其余条件都对上的名字"，照着抄

---

## 4. 长文本、输入、快捷键

| 场景 | 用什么 | 原因 |
|---|---|---|
| 短文本（几十字） | `desktop_type` | 模拟键盘，兼容性最好 |
| **长文本（几百字）** | `desktop_set_value` | 键盘注入会超时（实测 30 秒上限）；ValuePattern 一次写入 |
| 浏览器地址栏 | `Ctrl+L` + `type` | 比点地址栏稳 |
| 组合键 | `desktop_press_key` | 支持 `Ctrl+S` / `Alt+Tab` / `Enter` |
| 粘贴 | 先 `set_value`，别用 Ctrl+V | 剪贴板可能被占用 |

`set_value` 的返回会**回读确认**；不一致就是没写进去，别假设成功。

---

## 5. 前台、遮挡与激活

- 目标窗口被别的窗口盖住时，**点击会被拒绝**（`Refused`），这是保护，不是 bug
- 截图会警告"哪些采样点被遮挡"；看到警告就别拿那张图判断内容
- 要操作被盖住的窗口：先 `Alt+Tab` 或点它的任务栏/标签页把它提到前台
- **同进程的弹出菜单**（记事本的"编辑"）可以直接点，插件不会去激活它（激活会关掉菜单）
- 同进程的**普通窗口**盖住目标时会被拒绝——它只放行 owner 链上的弹出面

---

## 6. 急停（ESC）与恢复

- 按 ESC 后所有变更性操作被拒，**默认锁存**，不会自己过期
- 恢复只能由用户发起：说"继续"→ `desktop_resume`；或诊断输出里的命令
- 被拒绝时错误会带 `[retry=stop]`，**不要重试、不要绕过**
- 诊断会给出实际 helper 路径和闸门文件路径，**以诊断输出为准**，不要抄别处的路径

---

## 7. 光标装饰（实验性，默认关闭）

- 打开方式：`%TEMP%\dsc-cursor-fx.enable`（内容 `pose` 为无箭头款）或配置 `cursorFx: true`，然后**重启 DSH**
- 它只在**桌面操作进行中**出现；停手约 30 秒恢复系统光标
- **不支持多个 DSH 实例同时开启**（系统光标是全局资源）
- 素材随包发送，用户本地不需要图片
- 状态文件在 `%TEMP%\dsc-cursor-fx\<pid>\` 下，每个实例一个目录
- 光标不见了：控制面板 → 鼠标 → 指针 → 应用任意方案，最稳
- **别用 `taskkill /IM dsc-fx.exe /F` 批量杀**：会同时杀掉恢复进程，还可能误伤别的实例

---

## 8. 文件上传 / 原生对话框

浏览器里点"上传"会弹出**原生文件对话框**，它不在原窗口里：

```
1. 点击"选择文件"按钮
2. desktop_list_windows  找到新出现的对话框窗口（通常是浏览器进程）
3. desktop_type  "D:\完整\路径\文件.tgz"   ← 在文件名框里
4. Enter
5. 回到原窗口截图确认"上传完成"
```

注意：路径里有空格**不用加引号**（文件对话框自己处理）；但命令行里要加。

## 9. 常见错误码与处置

| 错误 | 含义 | 处置 |
|---|---|---|
| `StaleTarget` | 目标窗口没了/坐标处没窗口 | 重新 `list_windows` |
| `Refused` | 前台/遮挡/权限/白名单没通过 | 看消息里的原因，别重试 |
| `NotFound` | 名字没匹配上 | 按提示里的候选名重写描述符 |
| `AmbiguousTarget` | 匹配到多个 | 加 `aid=` 或更完整的 name |
| `Halted` | 急停生效 | 停，等用户恢复 |
| `HelperMissing` | 包装坏了/没装全 | 重装，别手动补文件 |
| `ReadOnly`/`权限` | 目标有更高完整性/受保护 | 用普通权限重试，或改用截图看 |

## 10. 性能与节制

- 每个 helper 调用约 100ms；连续截图很贵
- 同一批操作里，**先列一次窗口**，后续用传进来的 `windows` 结果，别反复列
- 截图只在"需要看"时拍，不要每步都拍
- OCR 兜底比截图慢，且只给文字位置，不证明可点

---

## 11. 什么时候它真的不行

- 游戏、自绘 UI、无无障碍信息的画布
- 多显示器 / 100% 缩放：**没验证过**（只验过单屏 125% / 150%）
- ARM64 / 32 位 Windows：没有打包验证
- Win10 2004 之前：装饰可能出现在截图里，且没有降级
- 应用私有光标：装饰会让位显示系统光标（`fx.log` 里记 `yield`），属预期

---

## 12. 给新手的 5 分钟上手

1. 让它"列一下窗口"（不用授权）
2. 让它"截一张记事本的图给我看"（会弹一次授权）
3. 在记事本里写几个字，让它"读一下界面内容"
4. 让它"点『编辑』菜单"（测按名字点）
5. 按一次 ESC，再让它点一下——观察它拒绝；说"继续"恢复

做完这五步，这个插件的脾气就摸清了。

---

## 13. 一条最重要的经验

**看返回，不只看成功。**

- `click` 的 `atElement` 告诉你点到了什么
- `set_value` 回读告诉你写进去了什么
- `screenshot` 的遮挡警告告诉你图能不能信
- 诊断告诉你 helper 路径和闸门状态

这个插件几乎每个动作都给了"证据字段"。**用证据判断，别用"没报错"判断。**
