## 1. A 项：弹出菜单（最严重）——已修

### 根因比报告写的更深一层

报告认为"落点校验按 HWND 判定，把同进程的另一个窗口误判成别的应用"。
**对了一半**。实际代码顺序是：

```
RequireActivated(目标窗口)      ← 先把主窗口激活到前台
WindowFromPoint(...)            ← 此时菜单已经被关掉了
root != target → 拒绝
```

激活主窗口**本来就会关闭它的弹出菜单**。所以不是"判定太严"，而是
"判定之前就把它要找的东西弄没了"。

### 修法

`Click` 现在先看清楚落点再决定：

```
1. WindowFromPoint → root → 取 hitPid
2. 若 root != target 但 hitPid == targetPid（同进程弹出窗口）：
     · 按同一应用对待（授权本来就是按 exe 给的）
     · **不激活**（激活会关掉菜单）
3. 其它情况维持原行为：拒绝，不替用户去点遮挡者
```

### 验证

`tools/test-menu-click.mjs`（真实 WinForms 菜单 + 真实鼠标注入）：

```
✓ 夹具窗口 hwnd=7800202，菜单栏 (445,361)
✓ 菜单栏点击被接受
✓ 菜单已打开，菜单项在 (511,390)
✓ 点击被接受（没有被"不是指定的目标窗口"拒绝）
✓ 落点是同进程的另一个窗口（2034470）—— 弹出菜单的预期行为
✓ 菜单项的 Click 事件执行了（日志有记录）
```

最后一条是关键：**不是"没报错"，而是菜单项的 Click 真的执行了**（夹具写日志）。

### 没覆盖的

- 只验证了"同进程弹出窗口"这一类。**跨进程的弹出菜单**（有的应用用独立进程做托盘菜单）
  仍然会被拒绝——那是少数情况，行为维持"拒绝而不是乱点"。
- `click_element` 对不可激活窗口的那条路没改：报告里它报"无法激活到前台"，
  现在**坐标点击已经能覆盖这类场景**，所以没有再动它（改动面越小越好）。

## 2. B 项：完整性级别（报告判断有误）

**代码里没有"按路径推断完整性"的逻辑。** `SelfIntegrityRid()` 走的是
`OpenProcessToken` + `GetTokenInformation(TokenIntegrityLevel)` + `ConvertSidToStringSid`，
读的是**进程令牌的真实值**。

同一份二进制报出不同级别，合理的解释是**父进程不同**：

- 从 DSH 的工具调用（沙箱内）启动 → 子进程是受限令牌 → `Low`
- 从普通终端启动 → 继承 `Medium`

这也解释了报告里"同一 shell、同一 TEMP、只有路径不同"的观察：两次的**调用方**不同，
而不是路径不同。

### 已做的

- 体检脚本和清单不再把 `Low` 说成"整个插件等于废的"，改成：
  **"Low = 这个进程是受限令牌启动的，请在普通终端重跑"**。
- 报告 C 项的提示语里也写了这一点。

### 没做的

没有加"沙箱标记"字段。理由：判断"是不是被沙箱启动"没有可靠 API，
按路径猜就是报告担心的那种做法，宁可不做。

## 3. C 项：体检脚本在沙箱里 EPERM——已加提示

`tools/smoke-report.mjs` 现在会捕获 `spawnSync` 的 EPERM，并在报告末尾明确打印：

```
⚠ 部分命令在受限沙箱里无法执行（spawn EPERM），上面的数据可能不完整。
  请在一个普通终端（不是 DSH 的沙箱终端）里重新运行本脚本。
```

没有改成"用临时文件重定向"——那只能绕过一部分命令，仍然读不到注册表和令牌，
半对半错的数据比明确失败更危险。

## 5. E 项：直接调 exe 会带窗口标题——文档标注，不改行为

`bin\dsc.exe list_windows` 是**调试入口**，会返回标题；插件层的 `desktop_list_windows`
刻意过滤掉。这是有意的：插件层是给模型看的，exe 层是给人排查用的。

已在该文档（本包 README 的"包内结构"附近）标注：**直接调 exe 会带窗口标题**。

没有加 `--no-titles` 开关：加一个"更安全的默认值"会让调试时看不到窗口，
排查遮挡问题时反而更难；而且这本来就不是给模型用的入口。

## 6. 卸载：清单已补完整章节

报告说"卸载路径是个空白"，属实。清单里补了：

1. 先从 `dsh.profile.bundles` 里移除 `dsh-desktop-control`（**别直接 pnpm remove**，
   否则会留下悬空引用 —— 报告里说的正是这个）
2. `pnpm remove dsh-desktop-control`
3. 重启 DSH
4. 验证三件事：工具消失、无 `dsc*` 残留进程、光标正常
