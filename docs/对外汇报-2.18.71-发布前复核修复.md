## 1. R1 授权按会话隔离

**根因**（复核定位准确）：`execute` 入口只往 ALS 塞了 `trace`，没塞身份；
`getSessionKey()` 恒为空 → 所有会话落进 `__default__` 授权表。

**修法**：

```js
async execute(args, exec) {
  const agent = exec?.agent ?? ctx.get('agents')?.currentInitiator?.() ?? null
  const sessionKey = (agent?.session?.id) ?? agent?.id ?? null
  if (!sessionKey && !allowSingleSession) throw Refused   // 受控拒绝
  return als.run({ trace, agent, sessionKey }, ...)
}
```

- 审批路径也改为**优先用 ALS 里的身份**（原先读 `currentInitiator()`，与授权用的不是同一个东西）
- 单会话模式要显式 `allowSingleSession: true`，默认关闭

**验证**（`tools/test-session-isolation.mjs`，真实记事本、真实审批桩）：

```
✓ A 被询问（共 1 次）
✓ B 被单独询问（共 2 次）
✓ 触发 session/disposed(A) 后再调用，会重新询问
✓ 无会话身份时受控拒绝
```

## 2. R2 装饰启动失败不再带走宿主

**根因**：`spawn()` 之后只监听 `exit`。启动失败是**异步** `error` 事件，没人接就是未处理事件，
Node 退出码 1。

**修法**：统一 `spawnManaged()`：立即监听 `error`/`exit`，只结算一次，清引用，
记一条受控警告；失败后**冷却 60 秒**，避免每次工具调用都重拉一个起不来的进程。
所有启动点都改用它，包括 `taskkill` 兜底。

**验证**（`tools/test-cursor-failure.mjs`，包里**故意不放** dsc-fx.exe 制造真实 ENOENT）：

```
✓ 宿主仍然存活（未因未处理的 error 事件退出）
✓ 工具本身照常返回结果
✓ 冷却生效：后续调用没有再尝试启动
✓ desktop_diagnose 可调用
```

## 3. R3 急停默认锁存

**根因**：JS 与 C# 两端默认 TTL 都是 60 秒，与文档和工具描述相反。文件还在，
原生端已经当成解除。

**修法**：两端默认改 `0`（永不自动过期）；`DSC_HALT_TTL_SECONDS` 仍可显式配置；
JS 侧读闸门失败时按"已拉下"处理（fail closed）。

**验证**（`tools/test-halt-latch.mjs`，真实 exe）：

```
✓ 70 秒后仍是 halted（锁存）
✓ 3600 秒后仍是 halted
✓ DSC_HALT_TTL_SECONDS=10 时按配置过期（逃生口保留）
✓ 没有闸门时不阻断
```

## 4. R4 裁剪 OCR 词框偏移

**根因**：裁图后只平移 `row.quad`，没平移 `row.words`；有 query 时候选用命中词的框，
局部坐标被当成原图坐标。

**修法**：抽出 `shiftOcrRows(rows, dx, dy)`（`visual-candidates.mjs`），
在"OCR 坐标进入候选库"的唯一边界同时平移行框与词框。

**验证**（`tools/test-visual-offset.mjs`）：

```
✓ 行框平移正确
✓ 词框平移正确
✓ 带 query 的候选中心 = 命中词中心
✓ 复核给的 (1130,310) 场景正确
✓ 无 query 时整行框也平移
```

## 5. R5 正常 dispose：先确认恢复，再退进程

**根因**：旧 `stop()` 写 stop → 立刻 `kill fx` → 立刻 `kill guard` → `taskkill /IM`。
Windows 上 `kill()` 是强制结束，fx 的 `finally` 可能没跑；`taskkill /IM` 还会殃及别的 profile。

**修法**：

```
写 stop → 有界等待 fx.blanked 消失（5 秒）→ 没恢复就 cursor_restore 再确认
        → 只 kill 自己起的两个进程（看门狗最后）→ 清 fx.stop
```

`Fx.cs` 退出时也自己清 stop 标记，避免旧标记让下一次启动立刻退出。

**验证**（`tools/test-cursor-dispose.mjs`，真实 dispose 处理器）：

```
✓ dispose 返回时光标已恢复
✓ 自己的装饰进程已退出
✓ 自己的看门狗已退出
✓ fx.stop 已清理
✓ 重新加载后装饰能启动
```

## 6. R6 菜单放行收紧

**根因**：只看"同 PID"就放行，一个进程的普通窗口盖住目标时也会被当成菜单。

**修法**：要求落点窗口的 **root owner 就是目标**（或目标自己的 owner），
即"挂在目标上的弹出面"；同进程的普通顶层窗口没有 owner 关系 → 拒绝。
（WinForms 的下拉不是经典 `#32768` 类，所以以 owner 关系为主，类名只作辅助。）

**验证**（`tools/test-menu-click.mjs`，真实 MenuStrip + 第二个同进程普通窗口）：

```
✓ 菜单栏点击被接受
✓ 菜单项点击被接受
✓ 落点是同进程的另一个窗口（弹出菜单的预期行为）
✓ 同进程普通窗口被拒绝（Refused）
✓ 菜单项的 Click 事件真正执行
```
